# System Think — Init Command

You are generating a curated architecture snapshot for use by the system-think
skill. Your goal is a compact, high-signal document — not an exhaustive dump.
The snapshot must be useful across multiple sessions without needing to re-read
the full project.

---

## Step 1 — Discover Architecture Artifacts

Glob and read the following, in priority order:

1. `CLAUDE.md` — project constraints, principles, working agreements
2. `README.md` — project overview if CLAUDE.md is absent or thin
3. Any files in: `**/arch/**`, `**/docs/**`, `**/design/**`
4. Any `.md` files whose names or contents reference:
   `state machine`, `user type`, `flow`, `schema`, `doctrine`, `constraint`,
   `model`, `identity`, `enrollment`, `purge`, `stack`, `PWA`, `offline`

Read everything that matches. Prioritise depth over breadth — a well-understood
small set beats a shallow large set.

---

## Step 2 — Extract Architecture Facts

From your reads, extract and organise:

### User Types
For each user type in the system:
- Name (canonical)
- Entry condition (how they appear in the system)
- Exit condition (how they leave or are removed)
- Key states or lifecycle stages
- Notable constraints or special handling

### State Machines
For each state machine:
- Entity name
- States (list)
- Valid transitions (from → to, trigger)
- Timed thresholds (any time-based gates or purges)
- Terminal states

### Identity & Enrollment Patterns
- How does identity get established? (auth, shadow record, guest, deferred?)
- Dual-path or multi-path patterns
- What happens on abandonment or timeout?

### Data & Information Systems
- Stores in use (DB, local, cache — name and purpose)
- Schema highlights (key entities and fields — not exhaustive)
- Purge or retention rules
- Offline/local storage patterns

### Architectural Doctrines & Constraints
- Named doctrines (e.g. Passive Participation Doctrine)
- Hard constraints (e.g. $0 MVP operational cost)
- PWA/offline requirements
- Privacy or regulatory rules

### Tech Stack Decisions
- Confirmed technologies and their roles
- Anything explicitly ruled out

### Existing Documented Flows
- Flow name, user type, brief summary (1 sentence each)
- Flag any flows that are partially documented or in progress

## Step 3 — Check for Existing Snapshot

Before writing, check for `.claude/skills/system-think/arch-snapshot.md`.

- If it exists: read the `Snapshot version` field and increment by 1
- If it does not exist: this is version 1

---

## Behaviour Rules

- **Curate, don't dump.** The snapshot should be readable by a human in 5 minutes.
- **Flag gaps honestly.** If a layer (e.g. state machines) has no documentation,
  say so in Snapshot Notes rather than omitting the section silently.
- **Never fabricate.** If something isn't in the project files, it doesn't go
  in the snapshot.
- **Overwrite is safe.** The snapshot is a derived artifact. The source files
  and system-think output logs are the record of truth.
